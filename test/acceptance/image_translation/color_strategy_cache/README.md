# 第五页恢复旧黑白修复缓存

2026-10-07，黑白和彩漫策略拆分后，阅读页恢复修复缓存时未传入当前策略。第五页的旧索引没有 `strategyId`，仍被接受，原英文蓝色填充消失但白边残留。材料来自该页真实阅读缓存；图片中的文字仅为测试数据。

`source.png` 保留原始 JPEG 字节，`observed.png` 为用户看到的旧修复背景，`pipeline_snapshot.json` 为原页重新运行 CTD 并匹配已翻译 OCR 框后的 14 个多边形。截图中的四行对白有 6826 个白色像素，旧黑白策略漏掉 2237 个；彩漫策略全部覆盖，6203 个蓝色文字像素也全部覆盖。

验收必须拒绝没有策略字段的旧缓存及不同策略的修复缓存；切换策略后也不能继续显示内存中的旧背景。模型重放检查原字填充和白边残留低于 1%。RGB 阈值仅用于此案例的测量，不参与生产掩码。

快速验收：`./tools/test_acceptance.ps1 -CaseId color_strategy_cache`。

模型重放：`./tools/test_acceptance.ps1 -WithModels -CaseId color_strategy_cache`。输出位于 `.dart_tool/acceptance/color_strategy_cache/`。

用户验收：在更新后的 Debug 应用打开第五页，确认旧残影缓存不再出现；点击重新翻译，检查四行原英文及白色描边消失、周围渐变与轮廓没有明显误擦。人工确认之前不登记 `verified` 成图。

同页蓝字变粉字：`translation.json` 保留真实异常译文及 OCR 字色。取样正确，但旧分组把乱序蓝字并入粉色对白，整组采用最大行的粉色样式。验收要求蓝色行按原文位置排序、与粉色行分开，共同渲染器输出蓝字白边。新增分组版本同时隔离旧单页及上下文翻译缓存。用户重新翻译时也需确认蓝色原文对应的中文仍为蓝色。
